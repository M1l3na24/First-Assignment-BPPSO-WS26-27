This repository contains my code for the first assignment.

It analyzes the BPI Challenge 2017 (BPIC-17) event log with process mining: simple event log analysis, process discovery with three algorithms (Alpha Miner, Heuristics Miner, Inductive Miner) including hyperparameter tuning, evaluation with the four quality dimensions (fitness, precision, generalization, simplicity), construction of a final BPMN 2.0 model, and an advanced data science analysis (Option 2: clustering of cases). The accompanying report is written separately but can be also found in this repo :)

## Two notebooks, two environments

The work is split into two notebooks that run in **different environments**:

| Notebook | Where it runs | What it covers |
|----------|---------------|----------------|
| `notebooks/assignmentI.ipynb` | **Locally** (VS Code + `.venv`) | Sections 3.1 to 3.3: setup, simple event log analysis, process discovery, quality metrics and final BPMN model |
| `notebooks/Advanced_Data_Science_Analysis.ipynb` | **Google Colab only** (GPU runtime) | Section 3.4 (Option 2): feature engineering per case and K-means clustering with GPU acceleration (cuML) |

The clustering workflow is the most computationally demanding part of the assignment: it builds a feature matrix for all 31,509 cases and trains K-means repeatedly for every candidate number of clusters and feature set, including extra runs to measure stability. That is why it runs in Colab, where a GPU is available. Keeping it in a separate notebook also leaves the process-mining pipeline of the main notebook untouched.

> The Colab notebook is **not** meant to run in the local `.venv`: it depends on RAPIDS (cuML) and a CUDA GPU, which are not part of `requirements.txt`.

## Running the main notebook locally (`assignmentI.ipynb`)

The project uses [uv](https://docs.astral.sh/uv/) to manage the virtual environment and dependencies.

### 1. Prerequisites

- **uv**. On macOS: `brew install uv`. Other systems: see the [uv installation guide](https://docs.astral.sh/uv/getting-started/installation/).
- **Python 3.12**. uv can install it for you if it is missing.
- **Graphviz (system program)**, required by PM4Py to draw Petri nets and process trees. The Python package alone is not enough.

  - macOS: `brew install graphviz`
  - Debian/Ubuntu: `sudo apt install graphviz`
  - Windows: install from the [Graphviz website](https://graphviz.org/download/) and add it to the `PATH`.

### 2. Create the virtual environment

From the project root:

```
uv sync
```

This creates `.venv/` and installs the exact versions recorded in `uv.lock`.

### 3. Run the notebook

**VS Code (recommended):**

I used VS Code, so I recommend it, however you may use the IDE of your preference.

1. Open the project folder and then `notebooks/assignmentI.ipynb`.
2. Click **Select Kernel** (top right), choose **Python Environments**, and select the `.venv` interpreter.
3. Run all cells in order (**Run All**).

**Terminal (optional):** activate the environment with `source .venv/bin/activate` (Windows: `.venv\Scripts\activate`) and open the notebook with your preferred Jupyter-compatible editor.

> IMPORTANT NOTE: The notebook lives in `notebooks/`, and it reads the dataset and writes its outputs with relative paths. Do not move the notebook, the `data_BPIChallenge2017_1_all/` folder or `generated_files/`, otherwise the paths will not resolve.

### Setting up from scratch without the lock file

If `pyproject.toml` and `uv.lock` are not available:

```
uv init --bare
uv python pin 3.12
uv add pm4py==2.7.23.11 pandas==3.0.6 numpy==2.5.4 matplotlib==3.11.2 ipykernel==7.4.0
```

All analyses and quality metrics are computed in Python with the open-source tools above; no commercial software is used.

## Running the advanced analysis in Google Colab (`Advanced_Data_Science_Analysis.ipynb`)

1. **Open the notebook in Colab.** Go to [colab.research.google.com](https://colab.research.google.com), choose the **GitHub** tab and paste the repository URL, or upload `notebooks/Advanced_Data_Science_Analysis.ipynb` directly.
2. **Select a GPU runtime:** *Runtime → Change runtime type → T4 GPU* (or better).
3. **Upload the dataset.** Put `BPI Challenge 2017.xes.gz` (from `data_BPIChallenge2017_1_all/`) in the Colab session storage, in the same folder as the notebook, since the notebook reads it as `"BPI Challenge 2017.xes.gz"`.
4. **Run all cells in order** (*Runtime → Run all*). The first cell installs `pm4py`.
5. **Download the outputs.** The notebook writes to `../generated_files`, which in Colab is a temporary folder outside this repository. Download the generated CSV and PDF files from the Colab file browser and copy them into the repository's `generated_files/` folder.

Notes for reproducibility:

- Every random seed is fixed (`random_state = 22`), and the notebook reads the same dataset file and event filter (`lifecycle:transition == "complete"`) as the main notebook.
- The cases are split by case ID into 60% training, 20% validation and 20% test, so no events of one case are shared between splits.
- Library versions in Colab can differ from the local lock file, so numbers can differ slightly from a local run. For the purpose of the assignment these small differences are not relevant.
- **Do not install `cuml-cu12`.** Current Colab GPU runtimes already ship with CUDA 13 and the matching RAPIDS packages (cuDF and cuML), so installing the CUDA 12 build creates a mixed environment. If you need to install RAPIDS, use the `cu13` build and restart the session before importing.

## Troubleshooting

These were some problems I went through so maybe this can help you!

**Local notebook**

- **`ExecutableNotFound: failed to execute 'dot'`**: Graphviz is not installed or not on the `PATH` (see prerequisites). Restart the kernel after installing it.
- **`FileNotFoundError` when loading the log**: the notebook or the dataset folder was moved or renamed (see the note in the local setup).
- **`IProgress not found` warning**: harmless, it only affects how progress bars look. Optionally run `uv add ipywidgets` and restart the kernel.
- **Loading the log takes about a minute or two**: Note that the log has 31,509 cases.

**Colab notebook**

- **`ImportError: libcudf.so: cannot open shared object file`**: the environment has a broken or mixed RAPIDS installation (for example after installing the `cu12` packages on top of a CUDA 13 image). Use *Runtime → Disconnect and delete runtime*, reconnect with a GPU and run the notebook again without installing cuML.
- **pip "dependency resolver" conflict messages after an install**: they are only warnings about packages that were already installed. The real failure is the `ImportError` that comes afterwards.
- **`FileNotFoundError` for `BPI Challenge 2017.xes.gz`**: the dataset was not uploaded to the Colab session, or the session was reset and the file is gone. Upload it again.
- **The clustering takes a long time**: check that the runtime really has a GPU (`!nvidia-smi`). The case-level feature building loops over all cases in Python, so a part of the runtime does not depend on the GPU.
